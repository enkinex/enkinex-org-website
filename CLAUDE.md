# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

`enkinex-website` is the public-facing Enkinex website. It currently ships a basic navigation and a landing-page mock that previews the **Enkinex Framework** — Enkinex's core offering, organised around three pillars (Semantic Driven Design, Contract Driven Lifecycle, Composable Mesh Architecture) that converge at the **SDMesh API**.

For the parent project (GitHub workflow conventions, skills, and permission posture), see [`../CLAUDE.md`](../CLAUDE.md). The conventions defined there — `branching-enkinex-repo`, `committing-enkinex-change`, `opening-enkinex-pr`, `reviewing-enkinex-pr`, `landing-enkinex-pr` — apply to this repo as well.

## Tech Stack

- **Framework:** [TanStack Start](https://tanstack.com/start) (SSR React) + [TanStack Router](https://tanstack.com/router) with file-based routing.
- **Runtime:** [Cloudflare Workers](https://developers.cloudflare.com/workers/) via `@cloudflare/vite-plugin` and `wrangler`. Worker entry: `@tanstack/react-start/server-entry` (configured in `wrangler.jsonc`).
- **Build / Dev:** Vite 8, `vite-tsconfig-paths`, `@tanstack/devtools-vite`.
- **UI Library:** [Mantine v9](https://mantine.dev/) (`@mantine/core`, `@mantine/hooks`, `@mantine/form`, `@mantine/dates`) with `postcss-preset-mantine` + `postcss-simple-vars` for breakpoints. SSR-safe via `ssr.noExternal: ["@mantine/*"]` in `vite.config.ts`.
- **Styling:** Tailwind CSS v4 (`@tailwindcss/vite`) coexisting with Mantine. CSS Modules for component-scoped styles (e.g. `Landing.module.css`).
- **Diagrams:** `reactflow` (used for the SDMesh diagram on the landing page).
- **Database / Backend:** [SurrealDB](https://surrealdb.com/) v3 multi-model database. Schema, seed data, and HTTP APIs are defined in **SurrealQL** under `src/database/` and applied by `src/database/init.ts`. The website calls SurrealDB's REST endpoint directly from server functions — no separate API service.
- **Forms / Validation:** `zod` for input validation in TanStack server functions.
- **Icons:** `lucide-react`.
- **Fonts:** Variable Inter and Noto Sans via `@fontsource-variable/*`.
- **Testing:** Vitest + Testing Library (`@testing-library/react`, `@testing-library/dom`, `jsdom`).
- **Linting / Formatting:** ESLint with `@tanstack/eslint-config`; Prettier with `prettier-plugin-tailwindcss`. Prettier rules: `endOfLine: lf`, `semi: false`, `singleQuote: false`, `trailingComma: all`, `printWidth: 80`, `tabWidth: 2`.
- **TypeScript:** strict, ESNext modules, `verbatimModuleSyntax: true`. Cloudflare types come from generated `worker-configuration.d.ts` (regenerate via `just typegen-dev`).

## Path Aliases

Two aliases resolve to `./src/*` — pick one and stay consistent within a file:

- `@/*` — TypeScript path alias (`tsconfig.json`).
- `#/*` — Node subpath imports (`package.json` `imports` field).

Both currently appear in the codebase.

## Routing Conventions

- File-based routing under `src/routes/`. Generated tree in `src/routeTree.gen.ts` (regenerated automatically by the TanStack Router Vite plugin — never hand-edit).
- The `{-$language}` directory makes language an **optional** path segment. Inside route loaders, default with `params.language || "en-US"`.
- Page data is fetched in `loader` via `getPage({ data: { page, language } })` (a `createServerFn`), and consumed in the component with `Route.useLoaderData()`.
- Per-page `<head>` / meta tags come from `getMeta(loaderData)` in `src/model/page/meta.ts`.
- Use `<MantineProvider>` and theme from `src/routes/__root.tsx`. Default colour scheme is **dark** — set both on `<ColorSchemeScript>` and `<MantineProvider>`.

## Mantine Usage

- Reach for Mantine components first; only drop to raw HTML or Tailwind when Mantine has no equivalent.
- **Always consult `docs/mantine/mantine-docs.txt` before building or customising a Mantine component.** That file is the canonical Mantine v9 reference for this project; treat it as you would the live docs.
- Theme is declared in `src/routes/__root.tsx` via `createTheme({ colors: { ... } })`. Custom palettes (`en-primary`, `en-secondary`, `en-accent`) follow Mantine's 10-shade tuple convention. Brand colors from `docs/brand.md` (Sumerian Gold `#C4953A`, Tablet Dark `#1A1A2E`, Enki Teal `#2A7A6A`, Clay Light `#F5F2EB`, Reed Brown `#8B7355`) should drive future palette work — see *Design System* below.
- Breakpoints come from `postcss.config.cjs` (`xs 36em`, `sm 48em`, `md 62em`, `lg 75em`, `xl 88em`); use Mantine's responsive props rather than hand-rolling media queries.

## Design System

The brand identity is fully specified in **`docs/brand.md`** — it is the source of truth for every visual decision (logo, color palette, typography, voice, imagery, iconography, layout, Mantine theme overrides). Read it before:

- adding or restyling components,
- generating SVG assets, vector graphics, or icons,
- introducing new colors, fonts, or spacing tokens,
- writing marketing or hero copy (the brand voice and positioning are defined there).

Key takeaways enforced by the brief:

- **Archetype:** Sage-Builder. Warm, authoritative, enduring; not a generic SaaS startup.
- **Avoid:** literal Sumerian imagery, circuit/network clichés, bright purple/blue gradients, overly trendy effects.
- **Prefer:** angular geometry inspired by cuneiform, warm gold + deep navy + teal accents, typography with intentional sharpness.

When the existing code conflicts with the brief (for example the placeholder palette in `__root.tsx` and the placeholder `Logo.tsx`), prefer the brief and update the code rather than the other way round.

## SurrealDB

### Schema layout

All schemas, data, and APIs live as **SurrealQL** files under `src/database/`:

- `table/*.surql` — `DEFINE TABLE` / `DEFINE FIELD`.
- `data/*.surql` — `CREATE … CONTENT` seed rows.
- `api/*.surql` — `DEFINE FUNCTION` / `DEFINE API` (SurrealDB-hosted HTTP endpoints).
- `table/remove.surql` and `api/remove.surql` — idempotent `REMOVE` counterparts.

`src/database/init.ts` runs the remove → create → seed → API sequence in order. **Add new schema by creating a `.surql` file and registering it in the appropriate `*_QUERIES` map in `init.ts`** — do not perform schema changes from application code.

### Local workflow

Configure via `.env.local` (template: `.env.local.example`). Required vars: `SURREAL_DATA`, `SURREAL_HOST`, `SURREAL_USER`, `SURREAL_PASS`, `SURREAL_NAMESPACE`, `SURREAL_DATABASE`, plus the `ENKINEX_*` path vars used by `init.ts`.

```bash
just surreal-start   # surreal start rocksdb://… on the configured port
just surreal-init    # npm run initdb — drops + recreates schema + seed
just dev             # vite dev on :3000
```

### Connection patterns

- **Server functions / SSR (`src/api/*.tsx`):** call SurrealDB's REST API via `fetch` using `DatabaseConfig.apiPath()` and `apiHeaders()`. Handlers run inside the Cloudflare Worker, so `DatabaseConfig` is constructed with `env` from `cloudflare:workers`.
- **CLI / Node scripts (e.g. `init.ts`):** use the `surrealdb` JS client through `getDatabase(config)`. `DatabaseConfig` falls back to `process.env`.

### Production binding

The Worker has no SurrealDB binding yet — `wrangler.jsonc` ships with all bindings commented out. When a remote SurrealDB endpoint is provisioned, store credentials as Wrangler **secrets**, not `vars`.

## Conventions & Gotchas

- **Don't edit `routeTree.gen.ts`** — it is regenerated by the TanStack Router plugin.
- **Don't edit `worker-configuration.d.ts` by hand** — regenerate via `just typegen-dev` after changing Worker bindings.
- Server functions (`createServerFn`) **must validate input with zod** (`.inputValidator(...)`) before reaching the handler. See `src/api/page.tsx` for the pattern.
- The Mantine v9 client requires `mantineHtmlProps` on `<html>` and `<ColorSchemeScript>` in `<head>` for SSR colour-scheme stability — both are wired in `__root.tsx`. Don't remove them.
- Tailwind v4 and Mantine coexist; reach for Mantine props/`Box`/`Group` for layout, and use Tailwind utility classes only where it would be awkward in Mantine.
- New SurrealQL files must be registered in `init.ts` or they will not be applied.
- Cloudflare Workers do **not** expose Node built-ins by default; `nodejs_compat` is enabled in `wrangler.jsonc`, but server-only code that uses `node:fs` (e.g. `init.ts`) must remain CLI-only — never import it from a route or server function.
- The current landing copy in `src/routes/{-$language}/index.tsx` is an unstyled mock. Treat it as content scaffolding — the structure (hero → SDMesh diagram → three pillar cards → SDMesh API CTA) is intentional and should be preserved while the visuals are built out from `docs/brand.md`.

## Adding Features — Checklist

1. **Content model first.** Add or update SurrealQL in `src/database/{table,data,api}/`, register the file in `init.ts`, and re-run `just surreal-init`.
2. **Types & validation.** Add TypeScript types under `src/model/` and zod schemas for any server-function inputs.
3. **Server function.** Expose data via `createServerFn` in `src/api/`, calling SurrealDB through `DatabaseConfig`.
4. **Route + loader.** Add the file under `src/routes/{-$language}/`, fetch in `loader`, set `head` via `getMeta`.
5. **UI.** Build with Mantine first, consulting `docs/mantine/mantine-docs.txt`. Style per `docs/brand.md`.
6. **Tests.** Add Vitest tests next to the unit they cover; run `npm run test`.
7. **Lint + format.** `npm run lint && npm run format` before committing.
